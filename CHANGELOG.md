## [Unreleased]

### Added

- `koBoardReactionStyles` (좋아요 · 싫어요 · 공감, the sample server's types), the Korean twin of `defaultBoardReactionStyles`; `apps/sample` and `apps/starter` pass it to the post detail by the device language.
- `BoardLabels.commentCountText` (`String Function(int)`, optional): the whole phrase of a comment count in the post list, so Korean reads `댓글 3` and not `3 댓글`; without it the list keeps `3 ` + `comments`.
- Korean sets `BoardLabels.ko()`, `LegalLabels.ko()` and `ImageUploadLabels.ko()` (polite 해요 style, with the Korean refusal reasons of the photo field), each with a test that the set names every field. The English defaults are unchanged. `iap` has no Labels class (its texts are the app's), so it has no Korean set; the sample and the starter hand them by the device language (`context.byLocale`).
- Social sign-in in the starter: with `--packages social-login-google|apple|kakao|naver` the sign-in page gets the buttons of the picked providers (same rules as the sample: a provider shows only with its values and when the server lists it), the providers' SDK sign-out joins the app's, an account without a password or address proves itself with a linked provider when deleting, and Apple is revoked before the delete. The native settings (Android manifest and Gradle placeholders, iOS URL schemes, Naver's Swift hooks, the `Social.xcconfig` and `social.properties` examples and their git-ignore lines, the Apple sign-in entitlement) are marker blocks that the stamp keeps only for the picked providers; the texts are in the starter's ARB files with `x-feature`. The stamp now renames `package:starter/` in every test file and reads `.gitignore` files. `skeleton_api_client` moved from dev to normal dependencies of the starter (Apple's revoke reads `ApiRequestError`). Not in the starter: the page that links a provider to a signed-in account.
- Korean and English: `skeleton_i18n` (`--packages i18n`; the language is the saved pick, else the device language, else Korean, kept on the device only; `LanguageMenu`; `arbProblems` to keep ko and en ARB files in step; catalog entry `i18n`, twin of react `i18n`). `*Labels.ko()` (polite 해요 style) for the Labels of `auth`, `push` and `notifications`; the others stay English by default. `apps/sample` and `apps/starter` keep their texts in ARB files (gen_l10n, Korean template, English second; the generated Dart files are git-ignored and written by `flutter pub get`) and hand the packages the right Labels; the sample has the language menu in Settings. The starter's ARB keys belong to packages through `x-feature` metadata, and the stamp drops the keys of packages that were not picked; with `i18n` the starter keeps the saved language and the menu. Not translated: `board`, `legal`, `iap`, `social-login*`, `storage` Labels and the promotional-consent texts of `push`.
- Profile picture (twin of react 78c8a2f): `skeleton_auth` `AccountMe.avatarEnabled` / `avatarKey` / `avatar`, `AccountApi.updateAvatar(key|null)` and `avatarAddress()`, and `ProfilePictureSection` with a `picker` slot (`auth` does not know `storage`): drawn only when the server answers `avatarKey`, save waits while a photo goes up, a refused photo (400 without field errors) has its own message, a converting picture says so. `apps/sample` and, with `storage`, the starter plug `ImageUploadField` (one photo) into it. There is no author-profile package in flutter yet.
- The starter carries the default screens of `board` (+ the photo field with `storage`), `notifications` (+ the realtime stream with `realtime`), `push` (Firebase start, sign-out hook, settings screen, Android in-front message) and `iap` (store screen, outcome message, cancel-in-the-store notice before deleting); `scripts/new-project.sh --packages ...` keeps the ones picked and removes the rest (screens, routes, wiring, dependencies, Android manifest and iOS plist entries). The markers are `// #if ids` / `// #endif` / `// #file ids` in the starter's files; a marker that names no package stops the stamp. Social sign-in screens are not in the starter yet.
- `skeleton_storage` (`--packages storage`): photo upload by presigned address (presign, PUT with progress and cancel and no app token, complete), `StorageFileRules` (none by default), `ImageUploadField` over `image_picker`, `StoredImage`; catalog entry `storage` (twin: react `storage`). `ErrorCodes.storageFileRejected` in `skeleton_api_client`.
- Notification inbox, realtime and promotional push consent: `skeleton_notifications` (list, unread badge, read marks, `notificationsChanged`), `skeleton_realtime` (SSE over the app's Dio), `skeleton_push` gets `pushFallbackLinkProvider` and `package:skeleton_push/advertising.dart` (advertising / night consent, withdrawal, two-year reconfirmation; now needs `skeleton_legal`), `skeleton_legal` gets `LegalApi.withdraw`. Catalog entries `notifications` and `realtime`, and `push` needs `legal`. `apps/sample` gets a Notifications tab with the unread badge, the stream open only signed in and in front, `/notifications` and `/settings/notifications` (the web's paths), a board comment row opening its post and an unknown path landing on the inbox. Not built: app icon badge number, system notification in front on Android, push-open report.
- Stage 3 (sign-up, legal, board, push, sample app): `skeleton_auth` sign-up, email verification, password reset and account deletion; `skeleton_legal` (sign-up consents, document page, `403 LEGAL.RECONSENT_REQUIRED` re-consent); `skeleton_board` (posts, nested comments, reactions); `skeleton_push` (FCM registration, settings, removal on sign-out); `apps/sample` wiring them; the starter gets the account and consent screens. Catalog entries `legal`, `board`, `push` and `app-sample` (`stampFlag.included: never`); a stamp always removes `apps/sample` and keeps `board` / `push` only with `--packages board,push`.
- `skeleton_iap` (`--packages iap`): in-app purchase checked by kotlin's `payment-iap`; catalog entry `iap`. `apps/sample` gets a Store tab (products, buy, restore, web checkout when the server's channel has the web, my subscription) and a "cancel it in the store" notice before account deletion. The Toss WebView attempt is kept on a local branch.
- Social sign-in with the providers' app SDKs, checked by kotlin's `auth-social` modules: `skeleton_social_login` (core: provider interface, nonce, `POST /auth/social/{provider}/token`, link and re-authentication tokens, a session only after the server accepted the token) and one package per SDK, `skeleton_social_login_google`, `_apple` (iOS only; revoke before account deletion), `_kakao`, `_naver` (all `--packages social-login-<provider>`; catalog entries `social-login`, `social-login-google`, `-apple`, `-kakao`, `-naver`). `skeleton_auth` deletes an account without a password (a mailed code, or a social re-authentication the app supplies). `apps/sample` gets the buttons, "Social sign-in" in settings and the native settings (git-ignored `Social.xcconfig` / `social.properties` with `.example` files); the Kakao and Naver logos are not in the repo.
- `scripts/new-project.sh <target-dir> <name> [--packages a,b] [--org com.example] [--prefix acme]` (string work in `tool/new_project/stamp.dart`) and `scripts/test-new-project.sh`; a path-filtered `new-project` workflow runs the test only when the stamper or what it rewrites changed.
- Capability catalog: `capabilities.json` + schema, generated `docs/capabilities.md` and `llms.txt`, and `dart tool/build_capabilities.dart --check` (CI) that ties entries to the real packages, `needs` to the pubspecs and, when kotlin-skeleton / react-skeleton are cloned next to this repo, backend module names and react twin ids to theirs. `tool/` is a workspace package with its own tests.
- `skeleton_api_client`: Dio client with the `value` / `values` / `pagination` envelopes, `ApiRequestError` (status, code, message, trace id, field errors), `ErrorCodes` for the codes the skeleton uses, header providers and an error hook.
- `skeleton_auth`: token stores (secure, memory), `AuthApi`, an interceptor that renews the access token on 401 with a single in-flight refresh, `AuthSession` (Riverpod notifier: checking, signed out, signed in), go_router redirect helpers, `LoginForm`. Backend contract test (tag `backend`) against a real kotlin-skeleton `apps/api`.
- `skeleton_ui`: design tokens as Dart constants, light and dark Material 3 themes, `LoadingView` and `ErrorView`.
- `apps/starter`: sign in, see `GET /auth/me`, sign out; stored-token restore on start; `--dart-define-from-file` settings; cleartext http only in debug builds (Android `src/debug` network security config, iOS Debug-only `Info-Debug.plist`); `INTERNET` declared in the main Android manifest. CI builds a debug APK (not yet run).
- Repository skeleton: Pub Workspaces root, Melos scripts (`analyze`, `format`, `test`), `skeleton_lints`, CI (format, analyze, test).
